# Reliability Release Runbook

## Release Paths
- Official desktop release: `npm run desktop:pack`
- Local raw pack debugging only: `npm run desktop:pack:raw`
- CI wiring check: `npm run release:reliability:ci`
- Full local gate without packing: `PYTHONPATH=. ./.venv/bin/python scripts/run_reliability_release_gate.py --desktop-mode electron --desktop-repeat 3`

`desktop:pack` is the release path. It runs the blocking reliability gate, writes the release evidence manifest, blocks on a dirty workspace, then invokes `desktop:pack:raw`. `desktop:pack:raw` skips the release preflight and must not be used as release evidence.

## Dirty Workspace Policy
- Non-dry-run `desktop:pack` blocks when `git.dirty=true`.
- `npm run desktop:pack -- --dry-run` allows dirty state so the release wiring can be tested before cleanup.
- `--allow-dirty` is only for local packaging experiments and is not a release path.

## Blocker Triage
- Top-level decision: `governance/audits/reliability_release_gate.json`
- Desktop dogfood details: `governance/audits/desktop_dogfood_gate.json`
- Runtime invariants: `governance/audits/runtime_invariant_report.json`
- Capability redteam: `governance/audits/capability_redteam_report.json`
- Product path gate: `governance/audits/product_path_release_gate.json`
- Doctor/package readiness: `governance/audits/beta_packaging_readiness.json`

Treat any blocker as release-stopping until the underlying artifact explains the failure and a fresh gate run passes.

## Legacy Workflow Reconciliation
- Inspect planned legacy mutations: `PYTHONPATH=. ./.venv/bin/python scripts/check_runtime_invariants.py --mode mark-legacy-safe --dry-run`
- Write eligible legacy marks: `PYTHONPATH=. ./.venv/bin/python scripts/check_runtime_invariants.py --mode mark-legacy-safe --write`
- Force-refresh existing marks only when intentionally re-auditing: add `--force --write`

`mark-legacy-safe` must not create synthetic approval actors, delete workflows, or change pending action business status. It only adds audit fields to eligible manual-review pending actions.

## Evidence Manifest
- Generate manually: `PYTHONPATH=. ./.venv/bin/python scripts/generate_release_evidence_manifest.py`
- Generated by pack preflight: `governance/audits/release_evidence_manifest.json`
- Manifest records git state, blocking config, gate artifacts, check summaries, and release policy.

`governance/audits/*.json` and `*.jsonl` are release evidence. Keep them out of product-code commits unless making an explicit evidence commit for a release.

## Evidence Bundle
- Inspect the bundle plan without writing files: `PYTHONPATH=. ./.venv/bin/python scripts/build_release_evidence_bundle.py --dry-run`
- Build a directory bundle: `PYTHONPATH=. ./.venv/bin/python scripts/build_release_evidence_bundle.py --command-log dist/release-evidence/rehearsal-command.log`
- Build a release-friendly zip: `PYTHONPATH=. ./.venv/bin/python scripts/build_release_evidence_bundle.py --command-log dist/release-evidence/rehearsal-command.log --zip`

The bundle copies the release evidence manifest, reliability gate, referenced audit artifacts, desktop dogfood run artifacts, runtime invariant ledger when present, and the command log. `bundle_manifest.json` is the bundle index; check `git.dirty=false`, `reliability_gate.decision=pass`, and the `missing_artifacts` list before attaching it to a release.

## Review Boundary
- Commit A: `agora/runtime_invariants.py`, `scripts/check_runtime_invariants.py`
- Commit B: `agora/release_evidence.py`, `scripts/desktop_pack_preflight.py`, `scripts/generate_release_evidence_manifest.py`, `scripts/desktop_electron_live_regression.js`, `package.json`, this runbook
- Commit C: tests only
- Optional evidence commit: selected `governance/audits/*.json` and `*.jsonl` from a named release run

Suggested staging commands:

```bash
git add agora/runtime_invariants.py scripts/check_runtime_invariants.py
git add agora/release_evidence.py scripts/desktop_pack_preflight.py scripts/generate_release_evidence_manifest.py scripts/desktop_electron_live_regression.js package.json docs/runbooks/reliability_release.md docs/macos_release_checklist.md .github/pull_request_template.md .github/workflows/reliability-ci.yml
git add tests/test_runtime_invariants.py tests/test_release_hygiene.py
```

Do not include `governance/audits/*.json` or `governance/audits/*.jsonl` in those commits.

Use the read-only checker before review:

```bash
PYTHONPATH=. ./.venv/bin/python scripts/check_review_boundary.py
PYTHONPATH=. ./.venv/bin/python scripts/check_review_boundary.py --strict
```

`--strict` fails only when staged evidence is mixed with staged product/test files.

## Release Rehearsal
- Start from a clean branch or clean worktree.
- Confirm `git status --short` is empty.
- Capture the full dry-run pack output: `mkdir -p dist/release-evidence && npm run desktop:pack -- --dry-run | tee dist/release-evidence/rehearsal-command.log`.
- Confirm `governance/audits/reliability_release_gate.json` reports `decision=pass`.
- Confirm `governance/audits/release_evidence_manifest.json` reports `git.dirty=false` and `release_policy.dirty_workspace=false`.
- Build the evidence bundle: `PYTHONPATH=. ./.venv/bin/python scripts/build_release_evidence_bundle.py --command-log dist/release-evidence/rehearsal-command.log --zip`.
- Confirm `dist/release-evidence/<timestamp>/bundle_manifest.json` reports `git.dirty=false`, `reliability_gate.decision=pass`, and the expected copied artifacts.
- Store rehearsal evidence as an external release artifact bundle by default. Use a separate evidence commit only when the release process explicitly requires committed evidence.
